# exam3

Дана таблица

```
CREATE TABLE scores(student_id INT PRIMARY KEY, hw1 INT, hw2 INT, hw3 INT);
```

В ней могут храниться данные об оценках студентов за домашние задания
(но могут и не храниться, то есть таблица может быть пустой).

Студенты иногда не делают задания, и тогда в качестве значения используется NULL.

По правилам курса студенты, которые как минимум 2 раза вошли в тройку лучших по одному из домашних заданий,
получают высший балл за курс автоматом.

Но есть нюанс: если работу сдавало менее 5 студентов, то вхождение в тройку лучших в таком задании не считается.

В частности, если для двух или трех заданий число сданных работ было менее 5, то никто высший балл автоматом не получит.

А если только в одном из заданий число сданных работ было менее 5, то для получения высшего балла автоматом нужно в обоих из оставшихся работ войто в тройку лучших.

Что будет в случае равного числа баллов, проще уточнить на примерах:

1. Лучшие результаты в порядке убывания:

```
(id: a12, hw1: 95), (id: a23, hw1: 87), (id: a55, hw1: 86), (id: a44, hw1: 80), ...
```

В тройку лучших попадают `a12, a23, a55`

2. Лучшие результаты в порядке убывания:

```
(id: a12, hw1: 95), (id: a23, hw1: 95), (id: a55, hw1: 86), (id: a44, hw1: 80)...
```

В тройку лучших попадают `a12, a23, a55`


3. Лучшие результаты в порядке убывания:

```
(id: a12, hw1: 95), (id: a23, hw1: 95), (id: a55, hw1: 86), (id: a44, hw1: 86), (id: a77, hw1: 80) ...
```

В "тройку" лучших попадают `a12, a23, a55, a44`


4. Лучшие результаты в порядке убывания:

```
(id: a12, hw1: 95), (id: a23, hw1: 90), (id: a55, hw1: 86), (id: a44, hw1: 86), (id: a77, hw1: 80) ...
```

В "тройку" лучших попадают `a12, a23, a55, a44`


5. Лучшие результаты в порядке убывания:

```
(id: a12, hw1: 95), (id: a23, hw1: 95), (id: a55, hw1: 95), (id: a44, hw1: 95), (id: a77, hw1: 80) ...
```

В "тройку" лучших попадают `a12, a23, a55, a44`


Формально это можно описать так: мысленно сортируем студентов в порядке убывания баллов, отбираем трех лучших, но
если четвертый, пятый и так далее, показали такой же результат, как и третий, то они тоже добавляются в "тройку".

## Предположения о данных

Предполагаем, что данных немного, не более 100 записей. 

## Ожмдаемое решение

Ожидается решение в вмде SQL-запроса. Не последовательность запросов. Не процедура/функция. 

Поместите его в файл `solution.sql`. В этом файле должен быть один запрос.

## Тесты

Любое решение должно быть протестировано. 

Оформите тесты в виде файлов `test1.sql`, `test2.sql`, ...

Каждый такой файл должен содержать последовательность запросов, после исполнения которой создается таблица `scores` указанной в задании структуры и ожидаемого (в соответствии с логикой конкретного тест-кейса) содержания.

Содержимое таблицы на момент завершения исполнения скрипта не должно зависеть ни от того, существовала ли таблица до запуска скрипта ни от ее содержимого на момент на начала (если она существовала).
